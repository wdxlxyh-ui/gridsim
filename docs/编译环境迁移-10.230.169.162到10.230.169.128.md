## 2. 重要安全要求

### 2.1 不复制旧服务器的 Git 凭据

当前本地仓库的 `origin` 配置曾出现过「凭据直接写在 HTTPS URL 中」的形式。迁移时禁止复制旧服务器的 `.git/config`，也禁止把密码、PAT、私钥写入本文档、Shell 历史或远程 URL。

推荐使用以下不带凭据的仓库地址：

```text
GitHub origin： https://github.com/wdxlxyh-ui/gridsim.git
GitHub SSH：   git@github.com:wdxlxyh-ui/gridsim.git
内部 GitLab：  git@git.eniot.io:qa/simulator.git
```

如果旧 `origin` URL 中的 Token 仍然有效，应在 GitHub 或对应凭据管理平台立即撤销并重新生成。新服务器只配置 SSH Key，或使用交互式 PAT，不把 PAT 放在 URL 中。

### 2.2 不在旧工作区上做破坏性清理

旧服务器工作区可能存在与本次迁移无关的未提交修改。迁移使用新服务器的新鲜克隆，不执行以下命令：

```bash
git reset --hard
git clean -f
git clean -fd
git push --force
```

如需回滚，只在新服务器的独立克隆目录中切换到已确认的旧提交或重新部署旧发行包。

### 2.3 迁移前保留旧服务

新服务器完成构建、配置恢复和健康检查之前，不停止旧服务器上的 GridSim 服务。旧服务器至少保留以下内容：

```text
旧源码目录
旧构建产物 dist/
旧运行目录 /home/envuser/IEC/gridsim
旧配置备份
旧服务 systemd 配置
```

## 3. Git 连接配置

### 3.1 Git 仓库信息

当前项目包含以下远程仓库：

| 名称 | 地址 | 典型用途 |
|---|---|---|
| `origin` | `https://github.com/wdxlxyh-ui/gridsim.git` | GitHub 主仓库，默认拉取来源
| `origin` SSH | `git@github.com:wdxlxyh-ui/gridsim.git` | GitHub SSH 方式；实际用户名和仓库名以仓库权限为准
| `gitlab` | `git@git.eniot.io:qa/simulator.git` | 内部 GitLab 仓库

> 项目实际 GitHub 仓库为 `wdxlxyh-ui/gridsim`。上表中的 GitHub SSH 地址应使用 `git@github.com:wdxlxyh-ui/gridsim.git`；配置前通过 `git ls-remote` 验证权限。

### 3.2 在新服务器生成构建专用 SSH Key

在 `10.230.169.128` 上执行：

```bash
install -d -m 700 /root/.ssh
ssh-keygen -t ed25519 \
  -f /root/.ssh/id_ed25519_gridsim_build \
  -C "gridsim-build-10.230.169.128"

chmod 600 /root/.ssh/id_ed25519_gridsim_build
chmod 644 /root/.ssh/id_ed25519_gridsim_build.pub
cat /root/.ssh/id_ed25519_gridsim_build.pub
```

将输出的公钥添加到：

1. GitHub 组织或仓库的 Deploy Key / SSH Key；
2. 内部 GitLab 用户或项目的 SSH Key。

如果 GitLab 只能通过公司网络访问，还需要确认 `10.230.169.128` 能访问 `git.eniot.io:22`。

### 3.3 配置 SSH Host

在新服务器创建 `/root/.ssh/config`：

```sshconfig
Host github.com
    HostName github.com
    User git
    IdentityFile /root/.ssh/id_ed25519_gridsim_build
    IdentitiesOnly yes

Host git.eniot.io
    HostName git.eniot.io
    User git
    IdentityFile /root/.ssh/id_ed25519_gridsim_build
    IdentitiesOnly yes
```

设置权限：

```bash
chmod 600 /root/.ssh/config
```

首次连接前，应按照组织的 SSH 指纹登记流程确认主机指纹，再写入 `known_hosts`。确认完成后执行：

```bash
ssh -T git@github.com
ssh -T git@git.eniot.io
```

GitHub 或 GitLab 返回的认证提示不一定是 Shell 登录成功，重点确认没有 `Permission denied (publickey)`。

### 3.4 配置远程仓库

在新服务器初始化源码前，可以先验证仓库访问：

```bash
git ls-remote git@github.com:wdxlxyh-ui/gridsim.git develop
git ls-remote git@git.eniot.io:qa/simulator.git develop
```

使用 GitHub 作为 `origin` 时：

如果组织要求从内部 GitLab 拉取，则使用：

```bash

  git@git.eniot.io:qa/simulator.git \
  /root/IEC-SIM/iec104-sim-master

```

检查结果：

```bash

git log -3 --oneline --decorate
git tag --list 'v3.3.*' --sort=-version:refname | head
```

预期结果：

- 当前分支为 `develop`；
- 远程地址不包含密码或 PAT；
- 可以读取 `origin/develop` 和目标发布标签；
- `git fetch --all --tags` 返回成功。

### 3.5 HTTPS + PAT 方式（备选）

如果暂时不能使用 SSH Key，使用不带凭据的 HTTPS 地址：

```bash
git remote set-url origin https://github.com/wdxlxyh-ui/gridsim.git
git remote -v
git fetch origin develop
```

认证时：

- Username：GitHub 用户名；
- Password：PAT，不是 GitHub 登录密码；
- 不要执行 `git remote set-url origin https://<token>@github.com/...`；
- 不要把 PAT 写入脚本、systemd 文件、项目文件或本文档。

如需临时缓存凭据，可使用组织批准的凭据管理器。不要默认使用明文 `credential.helper store`。

## 8. GridSim 运行环境迁移（可选）

如果目标只是迁移编译环境，可跳过本节。如果还要把 `10.230.169.162` 上正在运行的 GridSim 一并迁移到 `10.230.169.128`，必须先备份配置和运行数据。

### 8.1 旧服务器停止服务并备份

### 8.2 将配置备份传到新服务器

在旧服务器执行以下方式之一。

方式一：使用 `scp` 传输压缩包：

```bash
scp /home/envuser/IEC/gridsim/backups/config-pre-migration-$TS.tar.gz \
  root@10.230.169.128:/root/IEC-SIM/
```

方式二：使用 SSH 管道直接传输：

```bash
tar -C /home/envuser/IEC/gridsim/backups \
  -czf - "$(basename "$BACKUP")" | \
  ssh root@10.230.169.128 'cat > /root/IEC-SIM/config-pre-migration.tar.gz'
```

不要通过配置文件、命令行参数或聊天记录传输 Git 密钥、PAT 或服务器登录密码。

### 8.3 在新服务器部署运行包

在新服务器执行：

```bash
set -e
TARGET=/home/envuser/IEC/gridsim
SRC=$(ls -t /root/IEC-SIM/iec104-sim-master/dist/gridsim-v*-linux-amd64.tar.gz | head -1)

test -f "$SRC"
mkdir -p "$TARGET/backups"
```

如果配置备份是压缩包，先解压到临时目录核对：

```bash
mkdir -p /root/IEC-SIM/config-restore
rm -rf /root/IEC-SIM/config-restore/*
tar -xzf /root/IEC-SIM/config-pre-migration.tar.gz \
  -C /root/IEC-SIM/config-restore
find /root/IEC-SIM/config-restore -maxdepth 3 -type f | sort | head -100
```

停止目标服务器上可能存在的旧服务，然后替换程序文件。以下命令只清理运行目录中的程序和资源，不清理 `backups/`：

```bash
systemctl stop gridsim 2>/dev/null || true
bash "$TARGET/bin/stop.sh" 2>/dev/null || true
sleep 1

cd "$TARGET"
for item in bin config logs resources web GUIDE.md README.md; do
  rm -rf "$item"
done

tar xzf "$SRC" -C "$TARGET" --strip-components=1
chmod +x "$TARGET/bin"/* 2>/dev/null || true
mkdir -p "$TARGET/config" "$TARGET/logs"
```

恢复业务配置：

```bash
# BACKUP_DIR 应指向已核对过的配置备份目录
BACKUP_DIR=/root/IEC-SIM/config-restore/$(find /root/IEC-SIM/config-restore -mindepth 1 -maxdepth 1 -type d -printf '%f\n' | head -1)

if [ -d "$BACKUP_DIR" ]; then
  cp -a "$BACKUP_DIR/." "$TARGET/config/"
elif [ -d /root/IEC-SIM/config-restore/config ]; then
  cp -a /root/IEC-SIM/config-restore/config/. "$TARGET/config/"
else
  echo '找不到配置备份目录，停止部署，避免使用空配置覆盖运行环境。'
  exit 1
fi

rm -f "$TARGET/config/manifest.json"
```

如果采用目录方式直接传输，恢复命令为：

```bash
cp -a /root/IEC-SIM/config-backup/. /home/envuser/IEC/gridsim/config/
rm -f /home/envuser/IEC/gridsim/config/manifest.json
```

### 8.4 配置 systemd 服务

当前 GridSim 服务使用以下运行方式：

```ini
[Unit]
Description=Grid Simulator
After=network.target

[Service]
Type=forking
User=root
WorkingDirectory=/home/envuser/IEC/gridsim
ExecStart=/bin/bash /home/envuser/IEC/gridsim/bin/start.sh
ExecStop=/bin/bash /home/envuser/IEC/gridsim/bin/stop.sh
PIDFile=/home/envuser/IEC/gridsim/logs/pid
Restart=always
RestartSec=5

[Install]
WantedBy=multi-user.target
```

创建或核对 `/etc/systemd/system/gridsim.service`：

```bash

[Service]
```

`User=root` 是当前运行环境的兼容配置。迁移完成后，如需改为专用低权限用户，应单独设计文件权限、端口和设备访问，不要在迁移过程中同时修改运行用户。
