# 高级高危操作 Tab 实施计划

**Goal:** 在 GridSim Web 管理界面增加仅管理员可访问的「高级操作」Tab，并提供带重新输入当前密码、精确确认词和自动备份的数据库清理、全部业务配置删除和密码修改能力。

**Architecture:** 在现有 JWT 登录基础上新增后端 `AdminMiddleware`，仅包裹 `/api/v1/admin/` 路由，不改变现有普通 API 的兼容行为。SQLite 清理通过持久化服务的冲刷、备份和清空接口完成，配置删除通过 Manager 停止实例、ConfigStore 清空和各内存 Store 重置完成；所有破坏性操作先写入运行目录 sibling `backups/admin-ops/`，失败时不继续删除。

**Tech Stack:** Go 1.25.5、`net/http`、JWT v5、bcrypt、modernc SQLite、Vue 3、TypeScript、Element Plus、Vue Router、Axios。

---

## 安全边界和接口约定

### 管理员授权

- 请求必须带 `Authorization: Bearer <JWT>`。
- JWT 的 `role` 必须严格等于 `admin`；`operator` 和缺少角色的 Token 返回 `403`。
- 后端使用当前登录用户名从 `users.json` 查找用户，不接受前端提交的目标用户名，避免管理员修改其他账户密码。
- JWT 签名算法必须限制为 HMAC，拒绝非预期算法。
- 高危请求额外要求当前密码，密码不写日志、不返回响应。

### API

```text
PUT  /api/v1/admin/password
POST /api/v1/admin/database/clear
POST /api/v1/admin/config/clear
```

密码修改请求：

```json
{
  "current_password": "当前密码",
  "new_password": "新密码",
  "confirm_password": "再次输入新密码"
}
```

数据库清理请求：

```json
{
  "password": "当前密码",
  "confirmation": "CLEAR_DATABASE"
}
```

全部业务配置删除请求：

```json
{
  "password": "当前密码",
  "confirmation": "DELETE_ALL_CONFIG"
}
```

### 删除范围

数据库清理：

- 自动备份当前 SQLite 数据库；
- 停止全部实例和持久化采样；
- 冲刷异步写队列；
- 删除全部 `ts_<instance_id>` 时序表；
- 保留 SQLite schema 表、`users.json`、实例配置和备份文件。

全部业务配置删除：

- 自动备份整个 `config/` 目录；
- 停止全部实例；
- 清空 `instances.json`；
- 清空趋势模板和代理 Store 的内存及文件；
- 删除 `auto_changes/`、`recordings/`、`csv/`、`point-table-backups/` 和用户上传的 `.xlsx/.xls` 文件；
- 保留 `users.json`，避免删除配置后无法登录；
- 保留 `config/db/`，数据库由独立的「清理数据库」操作管理；
- 保留运行目录 sibling `backups/`；
- 不删除随发行包提供的 `config/py_simulator/` 运行时文件。

备份目录格式：

```text
<运行目录>/backups/admin-ops/<UTC 时间戳>-database/
<运行目录>/backups/admin-ops/<UTC 时间戳>-config/
```

**Files:**

- [ ] **Step 1: 抽取 JWT 解析逻辑并限制签名算法**

新增内部认证函数，解析 `Authorization: Bearer`，校验 Token 有效期和 HMAC 签名算法，将 `user_id`、`username`、`role` 写入 Context。现有 `AuthMiddleware` 复用该函数，保持既有公开路径行为。

JWT 回调必须拒绝非 HMAC 方法：

```go
if _, ok := token.Method.(*jwt.SigningMethodHMAC); !ok {
    return nil, fmt.Errorf("unexpected signing method %s", token.Method.Alg())
}
```

- [ ] **Step 2: 新增 `AdminMiddleware`**

```go
func AdminMiddleware(next http.Handler) http.Handler {
    return http.HandlerFunc(func(w http.ResponseWriter, r *http.Request) {
        ctx, err := authenticateRequest(r)
        if err != nil {
            http.Error(w, "unauthorized", http.StatusUnauthorized)
            return
        }
        role, _ := ctx.Value(RoleKey).(string)
        if role != "admin" {
            http.Error(w, "admin role required", http.StatusForbidden)
            return
        }
        next.ServeHTTP(w, r.WithContext(ctx))
    })
}
```

- [ ] **Step 3: 编写鉴权测试**

测试覆盖：缺少 Header 返回 `401`、错误 Scheme 返回 `401`、无效签名返回 `401`、`operator` 返回 `403`、`admin` 通过、非 HMAC 算法被拒绝。

### Task 2: 增加 SQLite Flush、备份和全量清理能力

**Files:**
- Modify: `internal/store/store.go`
- Test: `internal/store/store_test.go`

- [ ] **Step 1: 增加 writer flush 通道**

在 `Service` 增加：

```go
flushRequests chan chan error
```

`Open` 初始化该通道；`writerLoop` 收到 flush 请求后先写完当前 batch，再向调用方返回错误。`Flush` 必须在 Service 已关闭时返回错误，不能永久阻塞。

- [ ] **Step 2: 增加 `BackupTo`**

```go
func (s *Service) BackupTo(path string) error
```

实现顺序：`Flush()` → `PRAGMA wal_checkpoint(TRUNCATE)` → 创建目标目录 → 复制 SQLite 主文件。备份失败时返回错误，调用方不得继续执行清理。

- [ ] **Step 3: 增加 `ClearAll`**

```go
func (s *Service) ClearAll() (int64, error)
```

实现顺序：停止遗留 sampler → `Flush()` → 枚举并校验 `ts_` 表名 → 事务内删除全部时序表 → WAL checkpoint → `VACUUM` → 清零写入/丢弃计数。返回删除的时序表数量或记录数量。

不能直接删除运行中的 `.db`、`-wal`、`-shm` 文件。

- [ ] **Step 4: 编写存储测试**

新增测试：

1. `ClearAll` 删除两个实例表但保留 `schema_version`；
2. 清理前已写入的数据不可再通过 `Latest` / `History` 查询；
3. `BackupTo` 生成可读 SQLite 备份；
4. `Flush` 能写完异步队列且不会阻塞；
5. 已关闭 Service 调用 `Flush` / `ClearAll` 返回错误。

运行：

```bash
go test ./internal/store -count=1 -v
```

`handleAdmin` 按精确路径分派三个接口，未知路径返回 `404`，不允许通过字符串前缀误匹配其他资源。

- [ ] **Step 3: 实现当前密码校验和原子用户文件写入**

- [ ] **Step 4: 实现数据库清理 Handler**

校验 `password`、`confirmation == "CLEAR_DATABASE"`，先调用 `dataStore.BackupTo`，备份成功后调用 `mgr.StopAll()` 和 `dataStore.ClearAll()`。数据库未启用时返回 `503`，备份失败时返回 `500` 且不清理。

- [ ] **Step 5: 实现配置删除 Handler**

校验 `password`、`confirmation == "DELETE_ALL_CONFIG"`，先把整个 `config/` 复制到 admin backup，再调用 `mgr.ClearConfigs()`、`trendStore.Clear()`、`proxyStore.Reset()`，最后按既定范围删除业务文件。任一步骤失败立即返回错误并记录备份路径。

覆盖：无 Token、operator、错误密码、错误确认词、数据库未启用、备份失败、数据库清理成功、配置清理成功、密码修改成功、旧密码失效/新密码生效。破坏性测试全部使用 `t.TempDir()`，不得访问真实 `config/`。
