# 趋势模板持久化与运行目录优化实施计划

**Goal:** 将趋势模板从浏览器专属缓存迁移到服务端配置文件，统一配置、历史数据和日志目录职责，并完成版本发布、远程编译和编译服务器部署。

**Architecture:** 趋势模板使用 Go `internal/trend` 包管理 `config/trends/templates.json`，通过 REST API 提供列表、保存和删除能力；前端保留 `trend_panels` 作为当前浏览器工作区缓存，仅将共享模板迁移到服务端。实例日志从配置目录中分离，由 `--log-dir` 统一管理；SQLite 历史数据继续位于 `config/db`，不与模板 JSON 混合。

**Tech Stack:** Go 1.25、Vue 3、TypeScript、Axios、SQLite、ECharts、Vite、Git、Linux 远程编译与 systemd 部署。

---

## 1. 现状与问题

### 1.1 当前实现

- `web/src/views/TrendPage.vue` 的模板 CRUD 使用浏览器 `localStorage` 键 `trend_templates`。
- 当前面板和布局使用 `localStorage` 键 `trend_panels`。
- 测点历史已使用 `config/db/gridsim.db` 持久化。
- 实例配置位于 `config/instances.json`，自动变化策略位于 `config/auto_changes/`。
- `--log-dir` 仅创建目录，实例日志仍由 `NewInstanceLogger` 写入 `config/logs/`。

### 1.2 目标行为

1. 模板在换浏览器、清理浏览器缓存或重新部署后仍然存在。
2. 旧版本浏览器模板首次打开时自动迁移，不静默丢失。
3. 当前浏览器的临时工作区不覆盖其他浏览器的工作区。
4. 配置、数据库、备份、录制文件和日志目录有清晰边界。
5. 构建包能在远程服务器编译，部署时保留运行配置和历史数据。

## 2. 目标文件结构

```text
GridSim/
├─ bin/                              # 二进制和版本文件
├─ web/dist/                         # 前端静态资源
├─ resources/                        # 内置只读资源
├─ config/                           # --config-dir，业务配置和运行数据
│  ├─ instances.json
│  ├─ users.json
│  ├─ trends/templates.json          # 共享趋势模板
│  ├─ auto_changes/<instance>.json
│  ├─ db/gridsim.db                  # SQLite 历史数据
│  ├─ point-table-backups/<id>/
│  ├─ recordings/
│  └─ csv/
└─ logs/                             # --log-dir，运行日志
   ├─ output.log
   └─ <instance_id>-<protocol_port>/
      ├─ instance.log
      └─ instance.log.0~3
```

运行时数据不纳入 Git。`config/trends/templates.json` 及其临时文件加入 `.gitignore`，发行包只提供空配置目录，部署时从现有运行目录恢复用户数据。

## 3. 模板数据模型与 API

### 3.1 配置文件格式

文件：`config/trends/templates.json`

```json
{
  "version": 1,
  "templates": [
    {
      "id": "station-a",
      "name": "变电站 A",
      "panels": [
        {
          "kind": "collection",
          "trace_configs": [
            {
              "inst_id": "abc123",
              "inst": "实例 A",
              "ioa": 16385,
              "name": "有功功率",
              "unit": "kW",
              "alias": "",
              "color_idx": 0,
              "point_type": "AI"
            }
          ]
        }
      ],
      "created_at": 1787050000000,
      "updated_at": 1787050000000
    }
  ]
}
```

### 3.2 API

```text
GET    /api/v1/trend/templates
POST   /api/v1/trend/templates
DELETE /api/v1/trend/templates/{id}
```

- `GET` 返回按名称排序的模板列表。
- `POST` 根据 `id` 创建或覆盖模板，服务端补充或更新时间戳。
- `DELETE` 删除指定模板。
- 服务端校验模板 ID、名称、面板类型、实例 ID、面板数量和曲线数量。
- 保存使用临时文件后替换正式文件，避免直接覆盖产生半份 JSON。

## 4. 分任务实施步骤

### Task 1：新增趋势模板存储层

**文件：**

- Create: `internal/trend/store.go`
- Test: `internal/trend/store_test.go`

**实施内容：**

1. 定义 `TraceConfig`、`Panel`、`Template` 和版本化文件包装结构。
2. 实现 `NewStore`、`Load`、`List`、`Save`、`Delete`。
3. 缺少 `templates.json` 时按空模板处理。
4. 对 ID、模板名称、面板类型、数量进行校验。
5. 对外返回深拷贝，避免调用方绕过锁修改内部状态。
6. 使用 `sync.RWMutex` 保护并发读写。
7. 新增 round-trip、更新、删除、重复 ID、非法 JSON 和版本化格式测试。

### Task 2：接入后端 HTTP API

**文件：**

- Modify: `cmd/gridsim/main.go`

**实施内容：**

1. 启动时初始化 `trend.NewStore(configDir)` 并加载配置。
2. 注册模板列表、保存和删除路由。
3. 请求体限制为 2 MiB。
4. 对不存在模板返回 404，对非法数据返回 400，对存储失败返回 500。
5. 保存和删除操作写入结构化日志。

### Task 3：前端迁移到服务端模板

**文件：**

- Modify: `web/src/api/index.ts`
- Modify: `web/src/views/TrendPage.vue`

**实施内容：**

1. 增加 `TrendTemplate`、`TrendTemplatePanel` 和模板 API 客户端。
2. 增加前后端 snake_case 与现有前端 camelCase 的转换函数。
3. 将「覆盖保存」「另存为」「删除」改为 API 操作。
4. 首次加载时读取服务端模板。
5. 当服务端没有模板且浏览器存在 `trend_templates` 时执行一次迁移。
6. 旧版 `traces` 格式先按测点类型转换为面板格式再迁移。
7. 迁移全部成功后删除旧缓存；部分失败时保留浏览器兼容副本。
8. 服务端暂不可用时允许当前页面读取兼容副本，但明确提示模板未完成服务端保存。
9. `trend_panels` 继续只保存浏览器临时工作区。

1. 停止 `gridsim` 服务。
2. 备份 `/home/envuser/IEC/gridsim/config/` 到带时间戳的 `backups/` 目录。
3. 删除旧的 `bin`、`config`、`logs`、`resources`、`web`，保留 `backups`。
4. 解压最新 `gridsim-v3.3.6-linux-amd64.tar.gz`。
5. 恢复备份配置，保留 `config/trends/templates.json`、SQLite 数据库和实例配置。
6. 启动 `systemctl start gridsim`。
7. 检查 HTTP 200、版本号、实例数量和趋势模板 API。

健康检查：

```bash
curl -fsS http://localhost:8989/api/v1/status
curl -fsS http://localhost:8989/api/v1/trend/templates
curl -fsS http://localhost:8989/api/v1/instances
```

失败时先执行：

```bash
journalctl -u gridsim --no-pager -n 50
systemctl status gridsim --no-pager
```

回滚只使用已备份配置并重新部署上一个已知可用发行包，不执行 `reset --hard`、强制推送或删除远程分支。

## 5. 验收标准

- 新建模板后能在 `config/trends/templates.json` 中看到对应记录。
- 重启服务、换浏览器后，模板列表仍可加载。
- 旧版 `localStorage` 模板能自动迁移，迁移失败时不会被删除。
- 模板保存、删除和非法输入返回明确 HTTP 状态码。
- `--log-dir /path/to/logs` 后，实例日志只写入该目录。
- Modbus 实例日志目录使用实际 Modbus 端口。
- 配置目录、数据库目录和日志目录职责清晰，部署后原有配置和历史数据不丢失。
- 远程 `go test ./...`、`go vet ./...` 和完整 `./build.sh` 通过。
- 部署后 `/api/v1/status` 返回 HTTP 200，版本为 `3.3.6`，趋势模板 API 可访问。

## 6. 风险与回滚

| 风险 | 处理方式 |
|---|---|
| 旧模板字段格式不同 | 首次加载时兼容 `traces` 和 `panels` 两种格式 |
| 配置文件写入中断 | 临时文件写入后替换正式文件 |
| 服务端暂不可用 | 保留浏览器兼容副本并提示用户 |
| 部署覆盖运行数据 | 部署前完整备份 `config/`，部署后恢复 |
| 前端构建失败 | 不部署新包，保留当前运行版本 |
| 服务启动失败 | 查看 systemd 日志，使用上一版本发行包回滚 |
| 工作区存在其他人的修改 | 只暂存明确列出的本次文件，不使用 `git add -A` |
